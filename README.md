# Osito Cupping Lab

React/Vite app for running coffee cupping sessions, scoring samples, keeping session history, and exporting results.

## What changed

- Moved app code into `src/` modules (components, constants, helpers, styles).
- Added Vite project setup (`package.json`, `vite.config.js`, `src/main.jsx`).
- Bundled Tailwind through Vite instead of loading it from a CDN.
- Preserved the same UI and behavior.
- Kept recent bug fixes:
  - Safe history parsing from `localStorage`
  - Safer CSV escaping/download cleanup
  - No AI request unless `VITE_GEMINI_API_KEY` is set
  - No crash when cycling tags in sections without cycle support

## Folder layout

- `src/App.jsx`: main screen flow and state
- `src/components/`: reusable UI pieces
- `src/lib/cupping.js`: scoring/tag/csv/helpers
- `src/constants.js`: fixed data and config
- `src/styles.css`: custom and print styles

## Run it locally

1. Install Node.js 22.12+.
2. In this folder, run:

```bash
npm install
npm run dev
```

3. Open the URL shown in terminal. With the current Vite base path, the app runs at:

```text
http://localhost:5173/my-cupping-appV2/
```

## Local data

Sessions save immediately in the browser's `localStorage`. When the shared sync endpoint is configured, saved sessions automatically upload to the cupping spreadsheet. Offline changes stay pending across reloads and retry automatically when online. Clearing browser site data removes any local sessions that have not yet uploaded. The production app caches itself and its PDF assets after the first online visit. See [shared sync setup](server/SETUP.md).

## Shared cuppings and Panel Reports

- **Settings** remembers your cupper name on this device for future evaluations.
- **Share cupping** in History or the report screen creates an invitation for all or selected coffees. Everyone uses the same invitation link/code.
- **Join a cupping** opens the guest form. Quick and Full forms preserve tags, notes, and their separate score fields when switching. Both lexicons are available.
- Host controls close/reopen submissions and reveal/hide results. Guest evaluations are separate from primary records.
- Shared reports retain the existing flavor wheel and support vector PDF export.
- **Settings → Panel Report** retrieves evaluations by Sample ID or session/invitation code, supports explicit grouping across sessions, and saves fixed report editions with PDF export.

These features require updating the existing Apps Script deployment with the combined
source generated by `node scripts/build-apps-script.mjs`. Follow [deployment instructions](server/SETUP.md#shared-cuppings-and-panel-reports) before publishing the updated frontend.

## Deployment

The GitHub Pages workflow builds the app with Node.js 22 and publishes the `dist/` output. The Vite base path is configured for `/my-cupping-appV2/`.

## Optional: enable smart tag mapping

Create a `.env` file in the project root:

```bash
VITE_GEMINI_API_KEY=your_key_here
```

If this variable is not set, the app still works; smart mapping is simply skipped.
